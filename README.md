## 项目要回答什么

补贴是平台撬动增长的重要杠杆，但订单使用了补贴，并不代表补贴真正带来了增量。本项目没有预设“平台已经过度发券”，而是依次回答三个更可验证的问题：

1. 平台补贴使用是否存在高覆盖、高依赖或业务线高度集中的风险？
2. 哪些业务线应该先进入实验，哪些业务线必须先完成数据核查？
3. 如何把观察性风险转化为可执行、可监控的随机实验？

## 完整分析思路

### 1. 统一订单口径，建立平台基线

先将订单明细聚合到一单一行，计算覆盖用户、订单量、补贴订单占比和加权补贴率。加权补贴率使用平台记录补贴金额除以订单总交易额，避免小额订单对整体判断产生不成比例的影响。

平台样本覆盖 **94,888 名下单用户**、**1,999,688 笔订单**。整体加权补贴率为 **5.08%**，**51.71%** 的订单记录了正补贴。这里的“补贴订单”不等于用户收到优惠券，也不能直接证明订单由补贴带来。

### 2. 建立补贴使用分层，筛查依赖风险

以用户订单频次、历史补贴订单占比、交易金额和访问行为进行运营分层。在重复购买用户中，识别出 **13,354 名历史高补贴使用用户**，占重复购买用户的 **19.11%**。

该分层只用于缩小核查和实验范围，不把观察到的补贴使用习惯解释为价格弹性，也不直接生成减补名单。

### 3. 定位两类完全不同的业务问题

- **业务线 A：绝对提效空间。** A线贡献约 **71.3%** 的平台补贴总额，加权补贴率为 **5.08%**。金额集中不等于浪费，但意味着A线最值得优先开展可控实验。
- **业务线 E：结构异常与数据质量风险。** 样本期内E线 **100%订单记录正补贴**，加权补贴率为 **23.53%**。其中 **51.09%** 的补贴订单没有 `Coupon_id`，且所有E线订单的 `Shop_id` 均缺失，因此应先核查权益机制和数据链路，不能直接得出减补结论。

### 4. A线小范围测试：少发一些券，能否省钱且不伤订单

A线候选用户必须同时满足：历史A线订单不少于3笔、实验前28天仍有A线订单，且历史A线补贴订单占比严格介于20%与80%之间。最终获得 **18,804 名候选用户**。

当前方案是在历史数据上完成的模拟随机化，并非已经上线的实验：

| 组别 | 用户数 | 人数占比 | 策略 |
|---|---:|---:|---|
| Control | 9,384 | 49.90% | 维持现有补贴策略 |
| 频控组 | 9,420 | 50.10% | 单次优惠力度不变，28天内保留现行80%的补贴机会 |

三种比例含义不同：20%–80%是入选条件；49.90%/50.10%是人数分配；80%是频控强度。

正式实验的主指标应为**每名随机入组用户的贡献利润**；订单、活跃率、退款、投诉和跨业务线行为作为诊断或护栏。历史数据估计的人均订单双侧MDE约为 **3.25%**，当前样本无法严格验证“订单损失不超过2%”。

### 5. 对E线先核查，再决定是否实验

E线首先需要打通用户获券、领取、使用、核销和订单优惠链路，并确认补贴由平台还是商家承担。当前识别出的候选用户只能作为后续小流量试点的筛选线索，不能称为已经验证的低风险减补人群。

### 6. 形成平台级精细化策略

平台不应依据一次观察性分析直接全面减补。更稳妥的路径是：

1. 用历史补贴使用和自然购买证据筛选候选场景；
2. 对数据质量完成验收；
3. 通过随机对照试点测量真实增量；
4. 只有贡献利润改善且订单与体验护栏安全时，才逐步扩大频控。

## 使用了什么数据

数据范围为 **2023年1月1日至2023年6月30日**，包括三类比赛数据：

| 文件 | 粒度与用途 |
|---|---|
| `order_data.csv` | 订单与补贴记录，用于平台基线、业务线结构、补贴率和实验规划 |
| `user_profile.csv` | 100,000名用户的画像信息，用于用户覆盖、分层描述和随机化平衡 |
| `visit_data.csv` | 用户访问行为，用于活跃度描述、分层辅助和实验前基线 |

核心分析方法包括描述性统计、加权补贴率、用户级运营分层、线性与逻辑回归辅助诊断、跨业务线自然购买证据、分层随机化、CUPED规划以及MDE与非劣效能力评估。

## 关键证据边界

- 当前缺少完整的用户获券与过期数据，不能直接计算发券量、未核销率或证明“发券超过需求”。
- 补贴使用分层是运营筛查，不是用户价格弹性或因果依赖证明。
- A线随机分配是历史数据模拟，尚未产生生产曝光和实验结果。
- 当前数据缺少平台收入、补贴承担方和可变成本，无法计算真实贡献利润。
- E线 `Shop_id` 全部缺失，不能开展商户层补贴集中度分析。
- 原始订单存在重复 `Order_id` 行；当前分析采用订单内 `Reduce_amount` 求和口径，需由官方业务定义确认。

## English summary

This project evaluates subsidy-use efficiency, structural allocation risk and the risk of coupon over-issuance using six months of order, user-profile and visit data. It does not claim that over-issuance has already been proven. The analysis prioritises an A-line frequency-control pilot and an E-line data audit, while keeping simulated assignment, causal inference and profit-data limitations explicit.
